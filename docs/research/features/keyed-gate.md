# Keyed Gate (`HX_KEYGATE=1`, `tools/patch_keygate.py`, `src/sharc/keygate.asm`)

A noise gate block keyed from the Input block's gate, as a Boss NS-2 in the 4-cable method, in one block. Status tags as in [conventions.md](../conventions.md).

- **The model** [verified on unit, 2026-11-14]: Dynamics > Mono > Keyed Gate, preset ID 380, DSP cost 30, on a copy of the mono effect host whose member is primitive `0x012e` (registry `0x200058`, the third of `kit_patch_amp.UNUSED_SHARC_PRIMS`: NAM has the first, the Metronome the second). Entry 0 and 3 records are the Hard Gate's, so it lists and looks as a gate. Knobs pids 5..10: Key (Input, Self; the Horizon Gate's Mode record), Open Threshold, Close Threshold, Hold, Decay (the Hard Gate's records), Type (Smooth, Hard; the Wringer Fuzz's Fuzz Type record).
- **The key** [verified on unit, 2026-11-14]: the Input block's noise gate runs primitive `0x2720` (a gate core; stock process code `0x8e8f2`) once a channel, on the clean guitar, first in every frame. Its process entry is pointed at the kernel's `KG_TAP`, which, when a Keyed Gate has armed it (two calls after each Keyed Gate call), publishes the larger 16-sample peak of the two channels (`KG_PEAK`, `KG_STAMP` bumped) and runs the stock code. The Input block's gate must be On (Threshold −96 dB leaves the guitar ungated). A key not refreshed within 8 calls, or Key on Self, gates on the block's own input. The stock Noise Gate block runs `0x2720` too: one placed after a Keyed Gate becomes its key.
- **The gate**: a peak follower (20 ms fall), opening in 0.5 ms, Hold in 16-sample blocks, Decay as the time constant of every fall in gain. Type Hard closes to 0 after Hold; Type Smooth [verified on unit, 2026-11-15: much better than Hard, which cut notes off too abruptly] is a 1:4 downward expander under Close.
- **Placement**: its kernel sits in Block 3 right under the Metronome's kernel, its shared words right under that (`patch_keygate.place`). `tools/patch_comp.py` places the GR meter's DSP code under the Keyed Gate's words, whether or not the build has the Keyed Gate, so the two fit together.
- **Tests**: `tests/test_keygate.py` runs the kernel in the SHARC simulator (the tap, open and close on the key, Hold and Decay, Key on Self, the Input gate Off, Smooth against Hard).
